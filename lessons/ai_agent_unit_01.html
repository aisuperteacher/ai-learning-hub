01

先让它做一件具体的事

需求与验收 · 约 4 分钟，含下一节

你的任务

给 AI 工具新手，从三条材料中选 1 条适合做成 30 秒短视频的选题，写一句开场，并说明依据。

必须核对来源；查不到就说明未知。只交选题草稿，工具调用最多 5 次。

本单元怎样算有结果

  • 能追踪“动作 → 返回结果 → 下一动作”。
  • 能解释模型提出调用，和应用实际执行调用的区别。
  • 改变资料可用性后，能解释行动为什么改变。

本轮范围：理解与操作演示。连接真实模型、接入真实网页工具放到下一单元。

02

已有办法，什么时候就够用了？

做法在这个需求中怎么做适用情况
一次模型回答把已经核实的三条材料交给模型，让它选题。输入完整、无需继续查证时，通常已经足够。
Workflow · 固定工作流程序规定：逐条读来源 → 按标准筛选 → 生成开场。路径和异常能预先写清，强调稳定和可控。
LLM Agent · 大模型智能体模型根据已查到的内容，选择补查、换来源、换选题或结束。后续行动依赖新信息，难以预先穷举时可考虑。

这三条练习材料完全可以用 if/else 写完。我们选择它来观察机制；真实项目是否采用 Agent，还要看任务变化、延迟、费用和出错后的影响。

行业对 Agent 的称呼并不完全统一。本课用一个清晰的区分：关键行动是否由模型在运行时根据反馈选择。固定工作流也可以有分支、循环和工具调用；出现这些结构，本身不能证明它就是大模型 Agent。
03

先看图：反馈为什么会改变下一步

核心机制 · 约 6 分钟

一句话理解 AI Agent

在本课的大模型应用语境中，它是围绕目标，根据观察结果选择行动，并由应用执行这些行动的系统。可以经历多轮，也可以很快结束。

把它想成一位接到任务的选题助理：目标是交办事项，模型负责判断，工具是查资料的办法，工具返回是查到的证据，任务记录是工作笔记。

类比的边界：模型可能误读来源、选错工具，也可能编造看似合理的文字。输出“已查证”不能代替工具返回与原文依据。

和你熟悉的 Java 对上号

Tool Calling（工具调用）可类比模型生成一个结构化调用请求；应用检查后分发给函数或服务，再把结果传回模型。

写出 read_source("A") 只是请求或文本；执行器真正调用了工具，才产生外部操作。

稍后再研究：记忆、MCP、Skills

本轮只用当前任务的记录，不要求长期记忆。MCP 涉及工具连接方式；Skills 涉及可复用的做法和任务指导。它们可以帮助构建 Agent，但不负责替你决定每一步，也不是本轮的先修条件。

目标与约束产出是什么？做哪些事？何时停止？
模型基于已有信息，选择下一动作或回答。
工具与执行器应用校验请求，再运行函数或服务。
观察接收正文、状态或错误，更新任务记录。
循环与停止继续补信息，或在完成、受阻时收尾。

可观察的动作与返回

动作说明由教学编写，不是读取真实模型的内部思考。

    先看过一轮，再对照正常路径

    读取 A/B/C 摘要 → 读取 A 原文 → 得到“支持批量导出字幕文件”的返回 → 交付 A 的选题草稿。共 2 次工具调用。只有读取到的内容足够支持这个有限结论，才把它写成已核实。

    示范产物：选题“把几段视频的字幕一次导出来”；开场“你还在一段段导出字幕吗？先看看这个批量入口。”依据为虚构说明 A；不声称免费、不声称能准确识别所有音频。

    操作顺序与验收

    1. 资料齐全：走到结果，确认 2 次调用。
    2. A 来源打不开：重走，找到新增的补查动作。
    3. 在同一情境把预算改为 2，确认会带着证据缺口停止。

    验收对象是本页机制：调用顺序与返回对应，错误会改变路径，预算会终止循环。完成这些操作还不能证明你能独立设计 Agent。

    复用到真实工具环境的任务说明

    先确认那个环境确有读材料、读网页和检索能力。提示词本身不会安装工具，也不能授予应用没有的权限。

    查看完整任务说明
    任务：为 AI 工具新手，从我提供的 3 条材料中选 1 条适合 30 秒短视频的选题，写一句开场，并给出支持关键说法的原始来源。
输入：我会提供每条摘要及其来源链接。
判断：优先能演示、对新手有用的主题；逐步核对准备推荐的关键事实。
行动：仅使用当前环境实际提供并授权的只读工具。某来源打不开，可找同一产品的原始说明；说法冲突时以能核对的原文为依据，或保留未知。
约束：最多 5 次工具调用；不发布内容。不把“打算调用”写成“已经执行”。环境没有工具时，说明能力缺口，不编造查证结果。
停止：有足够证据支持 1 条合适选题后交付；预算耗尽或没有可用来源时，输出缺口及待核实事项。
输出：选题、目标受众、开场一句、事实依据及对应链接、仍待核实之处。简要列出实际用过的工具及结果状态。

    本次只运行了离线规则演示。上述说明用于下一轮真实环境实践，尚未在真实模型上执行或评估。

    卡住时看这里

    “点击了却没出现结果”：一次点击只展开一个阶段，继续到“结束”即可。“为什么三条没有全部查？”：本例只要求找到一条证据足够且适合的选题，未要求证明它是全网最佳。如果改为全面比较三条，查证范围也要随之改变。

    “为什么不能直接信工具？”：工具成功只表示拿到了返回；摘要和原文是否一致、来源是否真正支持结论，仍需要检查。这里的来源被简化为内置文字，真实网页还会有日期、适用地区和版本等条件。

    轮到你：先解释，再换一个条件

    复述与迁移 · 约 5 分钟；先做第一张即可

    卡住时只看一条提示

    把“提出一个调用请求”和“收到一次调用结果”分开。

    写完再展开参考

    模型生成的文字或调用请求不等于工具已经执行。需要应用实际调用的记录、工具返回，以及返回的原文是否支持结论。即使工具成功，也不能推出模型的解读一定正确。

    卡住时只看一条提示

    任务要求有可核对依据，是否一定要求从网页获得？

    写完再展开参考

    读取上传的原始说明，确认内容是否直接支持这个说法，并记录文件名、位置及适用条件。如果证据足够，就引用上传材料交付草稿；无需为了复现示范而强行继续搜索网页。这考查你能否围绕目标，依据当前可用信息选择行动。

    当前能力：待验证。请把你的第一张回答发回对话，我会依据回答定位缺口，再给一个变式。输入文字、点击按钮或看完演示，都不会自动变成“已掌握”。

    回答仅尝试保存在当前浏览器，不会发送出去；离线文件的记录不保证跨设备、不同打开方式或清理缓存后保留。导出续学卡可手动带回下一次对话。记录是否成功以按钮反馈为准。

    06

    有了结果，再补这三处细节

    回到需求 · 约 3 分钟

    什么时候出现怎样改进怎样验证
    把摘要或口号写成事实保存支持结论的原文位置，把不确定内容标为未知。逐句对照关键说法与依据。
    反复补查却不结束明确交付标准，由应用限制次数、时间或费用。让工具连续失败，检查是否按预算收尾。
    从“给草稿”扩展成“公开发布”明确可用工具与授权范围，发布等动作另行设计执行边界。只给只读工具时，程序不能执行发布。

    下一轮顺序：先把你给的一小组真实材料做成可核对的选题草稿；再处理工具失败、来源冲突和停止条件；最后才考虑批量运行及效率优化。

    用 Java 看机制：概念伪代码
    // 概念伪代码：不是可直接编译的 Java 项目。
while (!context.finished()) {
    Action action = model.choose(goal, context, toolDefinitions);
    if (action.isFinalAnswer()) {
        return action.answer();
    }
    if (budget.toolCallsExhausted()) {
        return reportUncertainty(context);
    }
    validateParametersAndPermissions(action);
    ToolResult result = executor.execute(action);
    context.add(action, result);  // 下一轮能观察到成功或错误
    budget.recordCall();
}

    关键变化在 model.choose(...)：运行时由模型选动作。真实应用还需校验工具结果与最终输出；不能只依靠模型遵守提示词。
