八个格子，怎样装下负数？
看懂补码与 −128～127

从「记录 −5，再加上 3」的完整任务出发，把二进制位权、取反加 1、范围和溢出连成一件事。

本单元只研究固定 8 位的有符号整数补码。所有运算面板都是保留低 8 位的教学模型；具体编程语言还会规定类型提升和溢出处理。顶栏“学完”只记录阅读，不代表已经掌握。

01 · 先看完整任务

记录 −5，增加 3，结果应该是 −2

设想一个只用 8 个二进制位保存整数的计数器。每个小格子叫一位（bit），只能是 0 或 1。我们要让它完成一件事：保存 −5，再加 3，最后读出 −2。

编码规则负责把整数对应到一串 0 和 1；加法负责处理这些位；解读规则负责把结果读回整数。接下来逐个解释这条主线。

先记住本课的关键：8 位补码的最左一位权重是 −128，其余七位仍是 64、32、16、8、4、2、1。因此 10000000 表示 −128，01111111 表示 127。
02 · 知识点在“编码与解读”环节

同一串 0 和 1，可以有不同的解释

十进制从右到左是个位、十位、百位。二进制逢 2 进 1，所以普通二进制从右到左的权重是 1、2、4、8、16、32、64、128。某位是 1，就把它的权重加进去；是 0，就不加。

例如，00000101 的两个 1 对应 4 和 1，所以值为 4 + 1 = 5。8 位共有 2 × 2 × … × 2 = 2⁸ = 256 种位形。

解释规则最左一位的权重其余位11111011 的值
无符号：只表示非负数+12864、32、16、8、4、2、1128 + 123 = 251
有符号补码：也表示负数−12864、32、16、8、4、2、1−128 + 123 = −5

硬件中的位形没有自带“−”号。我们使用什么解释规则，决定它表示哪个数。在补码规则下，最左位为 0 表示非负数；为 1 表示负数。它既能判断符号，也参与数值计算。

逐位实验：点一下，观察它贡献了多少

每个按钮上方是补码权重。默认位形代表 −5；先只点击最左位，观察数值变化。

按 8 位补码解释−5
按无符号解释251
同一个位形11111011

−128 + 64 + 32 + 16 + 8 + 2 + 1 = −5

最高位为 1：无符号值减去 256，就是补码值。

常见误解：补码后七位不表示负数的绝对值。10000101 是 −128 + 5 = −123，不是 −5。把“符号位 + 绝对值”当成补码，会用错规则。
03 · 手算：从整数得到位形

负数怎么写？固定八位，全部取反，再加 1

对于 0～127，直接写出二进制并在左边补 0 到 8 位。对于 −a（a 为 1～128 的幅值，也就是去掉负号后的大小），先把 a 写成 8 位无符号二进制，再把全部 8 位的 0/1 对换，最后加 1。

完整示范：−5

  1. 5 = 4 + 1，写成 00000101。先固定 8 位，前导零也算在内。
  2. 全部取反：11111010。0 变 1，1 变 0。
  3. 再加 1：11111011。这就是 −5 的 8 位补码。
  4. 读回检查：−128 + 64 + 32 + 16 + 8 + 2 + 1 = −5。
目标负数幅值的 8 位无符号写法全部取反再加 1：补码
−1000000011111111011111111
−5000001011111101011111011
−127011111111000000010000001
−128100000000111111110000000
−128 是最容易混淆的一行。第一步的 10000000 是“幅值 128 的无符号写法”；最后的 10000000 按补码规则解释为 −128。+128 没有 8 位有符号补码表示，这里并没有先保存一个可表示的 +128。

换一个整数，展开手算步骤

反过来，如何把补码读成十进制？

看见 11111011，先看最左位：1，说明它是负数。可以用两种方法互相检查：

方法 A：按位权相加

最高位贡献 −128；其余位合计 123。

−128 + 123 = −5

适用于所有 8 位补码，包括 −128。

方法 B：反算幅值

11111011 取反为 00000100，加 1 得 00000101，幅值是 5；原数为负，所以是 −5。

对 10000000 这样处理仍是 10000000，作为无符号幅值读出 128，再加负号。

04 · 连接手算规则与加法机制

为什么“取反加 1”就能表示相反数？

先看我们希望什么成立：5 + (−5) = 0。8 位计数器只能保留 8 位；如果二进制加法产生第 9 位，它在本模型里会被丢弃。

   00000101    幅值 5
+  11111011    −5 的位形（无符号读为 251）
= 100000000    需要 9 位，是无符号的 256

保留低 8 位：00000000 → 0

因此，−5 的编码可以选 256 − 5 = 251。5 与它相加，恰好达到 256，低 8 位回到 0。对任意幅值 a，同样有：

a + (256 − a) = 256 → 低 8 位为 0

这叫模 256的运算：相差 256 的整数会留下相同的低 8 位。它像一个有 256 个位置的循环计数器；这个类比只描述固定宽度的位形循环，普通数学整数没有在 127 后变成负数。

“取反”为什么对应 255 − a？

8 位全 1 的无符号值是 11111111 = 255。某一位原来是 1，取反后就是 0；原来是 0，取反后就是 1。原位形与取反后的位形，在每个位上正好加成 1，所以两者总和是 255。

全部 8 位取反 = 255 − a

取反后再加 1 = 256 − a

“取反加 1”正好算出了我们需要的负数编码。它是固定宽度下的计算方法，不是随意规定的一条口诀。

例如，5 取反后按无符号读是 250；再加 1 得 251。251 与 −5 相差 256，所以它们在保留低 8 位的加法中能对应起来。

05 · 推导最大值与最小值

为什么最大是 127，最小却是 −128？

将 256 种位形分成两半。最左位为 0 的 128 种表示 0～127；最左位为 1 的 128 种表示 −128～−1。

最高位为 0 · 无符号值0～127
↓
按补码解释：值不变0～12700000000 到 01111111
最高位为 1 · 无符号值128～255
↓
按补码解释：减去 256−128～−110000000 到 11111111

求最大值

负权重那一位取 0，其他正权重位全取 1：

01111111

0 + 64 + 32 + 16 + 8 + 4 + 2 + 1
= 127

求最小值

负权重那一位取 1，其他正权重位全取 0：

10000000

−128 + 0 + 0 + 0 + 0 + 0 + 0 + 0
= −128

也可以先把后七位的和记为 r。它最小是 0，最大是 127。因此：

  • 最高位是 0：数值是 r，所以范围为 0～127。
  • 最高位是 1：数值是 −128 + r，所以范围为 −128～−1。
128 个负数 + 1 个零 + 127 个正数 = 256
“零占一个位置”是数量解释：在这套补码分配中，最高位为 0 的一半包含 0，所以只有 127 个正数；另一半有 128 个负数。它不意味着所有有符号编码都必须如此，关键仍是补码的解释规则。

换成 n 位时，最高位权重是 −2n−1，其余 n−1 位的最大和是 2n−1−1。所以n 位补码范围是 −2n−1 ～ 2n−1−1。把 n = 8 代进去，就是 −128～127。

为什么 −128 取反加 1，还是它自己？

10000000 → 01111111 → 10000000。普通数学中，−128 的相反数是 +128；但 +128 超出 8 位补码范围。固定为 8 位后，位形只能回到 10000000。

因此，−128 有补码，却没有能放入同样 8 位有符号范围的正相反数。要保存 +128，需要更宽的有符号类型，例如 16 位；这不代表数学上 −(−128) = −128。

06 · 回到开头的完整任务

把 −5 和 +3 放回计数器

现在我们能解释整个过程：−5 编成 11111011，+3 编成 00000011，按普通二进制逐位相加，最后按补码读回。

   11111011    −5
+  00000011    +3
=  11111110

补码读回：−128 + 64 + 32 + 16 + 8 + 4 + 2 = −2

这样，同一套逐位加法规则就能处理这个正负数相加的任务。结果 −2 在范围内，所以它与普通数学整数加法一致。

8 位加法实验

仅模拟保留低 8 位。这里把“第 9 位进位”和“有符号溢出”分开显示，它们不是同一件事。

边界变化：127 再加 1

01111111 + 00000001 = 10000000。普通数学结果是 +128，超出 8 位补码范围；保留的位形会被解释成 −128。这就叫有符号溢出。

运算普通数学结果保留低 8 位后的读数第 9 位进位有符号溢出
−5 + 3−2−2无无
−5 + 500有无
127 + 1128−128无有
−128 + (−1)−129127有有

进位不是溢出的判定标准。最直观的检查是：普通数学结果是否落在 −128～127 内。对两个 8 位补码做加法，也可看“同号相加，得到异号”来判断有符号溢出。

这里的回绕结论针对固定保留 8 位的模型。具体语言不一定直接以 8 位做表达式运算。例如 Java 的 byte 相加通常先提升为 int；不能据此说 Java 的普通表达式 127 + 1 等于 −128。

可选思考：为什么 11111111 是 −1？

最高位贡献 −128，剩下七位全 1 贡献 127，所以总和是 −1。它按无符号规则解释才是 255。

可选思考：把最小负数“再减 1”会怎样？

−128 + (−1) 的普通数学结果是 −129，超出范围。对应位形相加为 10000000 + 11111111 = 1 01111111；只保留低 8 位得到 01111111，读成 +127。两个负数相加得到正的读数，说明发生有符号溢出。
